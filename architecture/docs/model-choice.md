# Выбор обучаемой модели

Для СМ7 принимаем модель GRU с одним слоем и 32 скрытыми признаками. Именно такая архитектура задана в пункте 8.1 версии 2 ТЗ. Поэтому сейчас задача выбора состоит в обосновании этого решения и точном описании реализации. Замена типа модели потребует изменения согласованных требований.

## Что модель должна выучить

На входе — 12 последовательных наблюдений. В каждом есть три числа: плотности перед светофорами 1, 2 и 3. Модель должна учитывать, как они менялись в течение последнего часа, и выбрать направление на следующие пять минут.

Например, один и тот же последний уровень плотности может завершать рост или снижение. Архитектура с памятью позволяет учитывать предшествующие наблюдения; полезность этого отличия проверяется на тесте.

Это классификация: ответ принадлежит одному из трёх классов. Числовой прогноз плотности не требуется. GRU — небольшая нейросеть для последовательностей, которую команда будет обучать на своих примерах; готовые знания о дорожной обстановке в ней отсутствуют.

## Как работает GRU простыми словами

Модель последовательно читает 12 наблюдений. На каждом шаге она обновляет внутреннюю память о прочитанном. Управляющие механизмы GRU определяют, какую часть прежнего состояния сохранить и как учесть новое наблюдение. После последнего шага линейный слой переводит память в три оценки классов. Механизм и форматы тензоров описаны в [документации PyTorch GRU](https://docs.pytorch.org/docs/2.15/generated/torch.nn.GRU.html).

Скрытый размер 32 означает 32 внутренних числа памяти. Это не 32 слоя, не 32 светофора и не 32 наблюдения.

## Сопоставление вариантов

Следующая таблица отражает проектное решение, а не результаты экспериментов.

| Вариант | Как использует вход | Решение для проекта |
|---|---|---|
| Минимум последней строки | Учитывает только текущие три плотности | Обязательный базовый алгоритм для сравнения |
| Обычная полносвязная сеть | Может получать все 36 чисел в фиксированных позициях | Возможная альтернатива, но ТЗ задаёт GRU |
| LSTM | Обрабатывает последовательность с дополнительным состоянием памяти | При том же размере имеет больше параметров; необходимость усложнения не установлена |
| GRU | Обновляет память при чтении последовательности | Выбрана по ТЗ; компактная архитектура для реализации и объяснения |

По формулам размеров весов PyTorch, GRU с входом 3 и памятью 32 содержит 3 552 параметра, а выходной слой 32 → 3 добавляет 99. **Всего 3 651 обучаемый параметр.** Аналогичная однослойная LSTM с тем же выходным слоем содержит 4 835 параметров. Расчёт: GRU — `3×32×3 + 3×32×32 + 2×3×32 + 32×3 + 3`; LSTM использует множитель 4 вместо 3 в рекуррентной части. Формы весов: [GRU](https://docs.pytorch.org/docs/2.15/generated/torch.nn.GRU.html), [LSTM](https://docs.pytorch.org/docs/2.15/generated/torch.nn.LSTM.html).

Меньшее число параметров — аргумент в пользу простой реализации, но оно не доказывает более высокую точность или конкретное время обучения. Работу на заданном CPU и длительность обучения нужно измерить после интеграции.

## Точная схема

```text
Плотности:                [размер пакета, 12, 3]
Деление на 200:           тот же размер, диапазон от 0 до 1
GRU:                     input_size=3, hidden_size=32, num_layers=1
                         batch_first=True, bidirectional=False
Последняя память h_n[0]: [размер пакета, 32]
Linear(32, 3):           [размер пакета, 3], оценки до softmax
Во время прогноза:       softmax → три вероятности → argmax + 1
```

Начальная память обнуляется для каждого независимого окна. Состояние между пакетами не переносится. Двусторонняя обработка и дополнительные слои в выбранную архитектуру не входят.

## Обучение и проверка качества

Во время обучения применяется CrossEntropyLoss к оценкам **до softmax** и индексам классов 0, 1, 2. Таков [контракт CrossEntropyLoss в PyTorch](https://docs.pytorch.org/docs/2.15/generated/torch.nn.CrossEntropyLoss.html). Внешние номера светофоров — 1, 2, 3. Adam использует шаг 0,001; пакет — 128; максимум — 30 эпох. Лучшие веса определяются по минимальной валидационной потере, с остановкой после пяти эпох без улучшения.

Сравнение проводится с минимумом последней строки по Accuracy, F1-macro и средней избыточной плотности. Заранее обещать преимущество нейросети нельзя. В генераторе ТЗ есть независимый случайный шум: история не позволяет точно восстановить его будущую реализацию. Это ограничивает предсказуемость задачи независимо от выбранной архитектуры.

Вероятности softmax — оценки модели, их нельзя автоматически считать подтверждённой частотой правильных решений. Для проекта сохраняются исходные вероятности без предварительного округления.
