# Соглашения между модулями

Эти интерфейсы позволяют проектировать модель и сценарии запуска до появления модуля данных. Они не требуют от ответственного за данные определённого внутреннего устройства его кода.

## Граница с ответственным за данные

Внешний CSV по ТЗ содержит `timestamp,density_1,density_2,density_3`. Плотность измеряется в автомобилях на километр одной полосы; допустимы конечные значения от 0 до 200. Время означает конец завершившегося пятиминутного интервала. Полный период, шаг, округление и разбиение задаёт ТЗ; генерация и проверка этого CSV выполняются в модуле коллеги.

Модель не зависит от имени CSV и конкретной библиотеки чтения. Её граница — массивы, перечисленные ниже. Адаптер подключит фактический результат работы коллеги к этому соглашению.

| Операция адаптера | Вход | Выход |
|---|---|---|
| `load_training_splits` | Путь к CSV, настройки | Отдельные train и validation |
| `load_test_split` | Путь к CSV, настройки | Только test для итоговой оценки |
| `load_history` | Путь к истории, время t | Последние 12 последовательных строк до t и само t |

Функции — проект интерфейса, они пока не реализованы. Материализация всех окон в отдельные файлы не обязательна: модуль может возвращать Dataset или формировать пакеты по запросу.

## Пакет для обучения

- `X`: float32, форма `[N,12,3]`, значения в исходных единицах, столбцы строго 1, 2, 3, время от старого к новому.
- `y`: целочисленный массив `[N]`, классы 0, 1, 2. При равных минимальных плотностях следующего интервала выбирается первый минимум.
- `forecast_origin`: N временных меток конца входных окон.
- Для test дополнительно `target_density`: float32 `[N,3]` с фактическими плотностями следующего интервала, только для метрик.

Деление на 200 выполняет общий слой подготовки входа непосредственно перед моделью, одинаково при обучении, оценке и прогнозе. Адаптер возвращает исходные плотности — так исключается двойная нормализация. Метки и будущие плотности передаются отдельно и никогда не входят в X.

Окно и целевая строка принадлежат одной части. Ожидаемые размеры по ТЗ: train — 147 357 примеров, validation — 31 567, test — 31 568. Перемешивать можно только train. Формирование и проверку окон реализует ответственный за данные; эти числа нужны как условия совместимости.

## Вызов модели

`forward(X_normalized) → logits`: вход float32 `[N,12,3]` на CPU; выход `[N,3]` до softmax. Модель не получает дату, правильный ответ или будущую плотность. В оценке и прогнозе используется общий сервис загрузки модели и предсказания, поэтому правила выбора класса не расходятся.

## Сохранённая модель

`models/best.pt` содержит `state_dict` лучшей модели. Соседний `models/metadata.json` содержит версию формата, имя архитектуры, размеры слоёв, порядок признаков, длину окна, делитель 200, шаг и горизонт, лучшую эпоху и её потерю, настройки обучения, версии библиотек, версию кода и идентификатор исходного набора.

Загрузчик проверяет совместимость метаданных, создаёт архитектуру и загружает веса на CPU. Несовпадение размеров или порядка признаков отклоняется с объяснением. Неполный комплект весов и метаданных считается ошибкой. Финальные веса, контрольный вход и эталонный JSON позже явно добавляются в Git; `.gitignore` пока защищает рабочие каталоги от случайного добавления промежуточных файлов.

## Результат прогноза

```json
{
  "forecast_origin": "2025-12-01T12:00:00",
  "target_interval_start": "2025-12-01T12:00:00",
  "target_interval_end": "2025-12-01T12:05:00",
  "selected_light": 2,
  "probabilities": [0.1, 0.6, 0.3]
}
```

Это иллюстрация формата, не результат обученной модели. Числа вероятностей конечны и находятся в `[0,1]`; сумма отличается от единицы не более чем на `0.000001`. Порядок вероятностей — 1, 2, 3. Во время сохранения значения заранее не округляются. Печать пояснений в JSON-файл не допускается.

## Результат оценки

`results/metrics.json` содержит для обоих алгоритмов Accuracy, F1-macro, среднюю Δρ и матрицу ошибок 3 × 3. Строки матрицы — правильные классы, столбцы — предсказанные, порядок 1, 2, 3. При нулевом знаменателе F1 класса принимается равным нулю.

`results/test_predictions.csv` содержит столбцы `forecast_origin,true_light,model_light,baseline_light,target_density_1,target_density_2,target_density_3,model_excess_density,baseline_excess_density`. Для каждого алгоритма Δρ — фактическая плотность выбранного направления минус минимальная фактическая плотность. При равных минимумах Accuracy использует метку меньшего номера; Δρ допускает нулевую потерю для любого минимального направления.

## Ошибки

Будущие команды возвращают 0 при успехе, 1 при ошибке входа, несовместимости артефактов или ошибке выполнения, 2 при неверных аргументах. Сейчас зарезервированные, но не реализованные команды также возвращают 2. Ошибка содержит понятную причину и направляется в stderr. Исходный CSV не изменяется. Неудачный запуск не должен заменять ранее сохранённый корректный результат частичным файлом.
