# Инфраструктура и простой запуск

Пользователь работает с одним файлом `START.cmd` в Windows или с `run.py` в Ubuntu. Запуск открывает консольное меню; все действия используют одни и те же программные модули, что и отдельные команды. Рабочее прогнозирование не должно повторять обучение.

## Что нужно сейчас

Для каркаса достаточно Python 3.12 и стандартной библиотеки. Для просмотра HTML-схемы нужен обычный браузер. `START.cmd` выбирает сначала локальное окружение `.venv`, затем Python 3.12 через `py`, затем проверяет команду `python`. Все пути привязаны к расположению файла запуска, поэтому каталог с пробелами и кириллицей поддерживается.

Запуск не устанавливает библиотеки, не скачивает данные и не изменяет компьютер. Для просмотра схемы можно непосредственно открыть `docs/overview.html`.

## Целевая среда полной программы

| Компонент | Решение |
|---|---|
| Основная ОС по ТЗ | Ubuntu 24.04 |
| Разработка на имеющемся ПК | Windows, Python 3.12; отдельная проверка Ubuntu перед приёмкой |
| Вычисления | CPU; 16 ГБ памяти и Ryzen 5 4600H или аналог по ТЗ |
| Обучение и прогноз | PyTorch |
| Работа с таблицами и массивами | NumPy и pandas при необходимости интеграции |
| Графики журнала обучения | Matplotlib |
| Установка | Одно локальное окружение `.venv`, закреплённые версии в requirements.txt |
| Хранение | Локальные каталоги data, models, results |

CPU-установка поддерживается PyTorch: [официальная инструкция](https://pytorch.org/get-started/locally/). Конкретные версии библиотек будут закреплены после проверки полного набора на Python 3.12 в Windows и Ubuntu. Текущий каркас сторонних зависимостей не использует, поэтому файл зависимостей пока не создаётся.

Первоначальная установка ML-зависимостей может требовать интернета. После установки и получения данных и весов программа работает автономно. Docker, облако, API-сервис, база данных и видеокарта в принятую архитектуру не входят.

## Поведение единого меню после интеграции

1. **Прогноз:** выбрать CSV и время t; проверить историю и наличие модели; выдать результат в консоль и JSON.
2. **Обучение:** явный выбор пользователя; проверить данные; обучить и сохранить лучшие веса с журналом.
3. **Оценка:** отдельный запуск на test с сохранением метрик и решений обоих алгоритмов.
4. **Проверка готовности:** показать наличие среды, входа, весов и совместимость настроек.
5. **Архитектура:** открыть объяснение устройства проекта.

При отсутствии модели меню объясняет, что обучение ещё не выполнено или веса не получены. При отсутствии CSV показывает требуемый формат. Параметры запуска выбираются внутри меню, чтобы обычному пользователю не приходилось запоминать команды.

## Отдельные команды после интеграции

Для приёмочных проверок сохраняются отдельные режимы `generate`, `prepare`, `train`, `evaluate`, `predict`. Их полные аргументы будут добавлены одновременно с реализацией; сейчас эти имена только зарезервированы. Генерация и подготовка подключаются из работы коллеги. Пункт подготовки может вызываться внутри обучения, но прямой режим сохраняется для диагностики.

Веса и журнал обучения, метрики теста и результат отдельного прогноза хранятся раздельно. Повторный прогноз не меняет лучшую модель. Запуск оценки не запускает обучение автоматически.
