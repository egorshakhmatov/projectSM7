# Инфраструктура и простой запуск

Пользователь дважды нажимает `START.cmd` в Windows. Открывается отдельное окно программы с кнопками. При первом запуске среда готовится автоматически, при последующих проверяется локально. В Ubuntu сохраняется консольный запуск через `run.py`; автоматическая установка проверена только в Windows.

## Что нужно сейчас

`START.cmd` запускает `setup.ps1`. Подготовщик проверяет 64-разрядный Python 3.12 с tkinter и виртуальную среду `.venv`. Если подходящего Python нет, скачивает подписанный установщик 3.12.10 с python.org и устанавливает его в `.runtime/Python312`. Подпись Python Software Foundation проверяется до запуска. Системный PATH не изменяется. Python 3.12.10 выбран как последний полный выпуск 3.12 с официальным Windows установщиком; более новые выпуски 3.12 содержат исправления безопасности и распространяются без такого установщика. Источник: [Python 3.12.10](https://www.python.org/downloads/release/python-31210/).

Затем проверяются версии и фактическая загрузка PyTorch, NumPy, pandas и Matplotlib. Недостающие компоненты устанавливаются автоматически в `.venv`: PyTorch из официального CPU-репозитория, остальные библиотеки из PyPI. Закреплённые версии и Windows файл ограничений исключают произвольный выбор новых версий. При исправной среде установки и сетевых запросов нет. Блокировка предотвращает одновременную подготовку одной среды несколькими запусками.

Первый запуск на другом ПК требует интернет и свободное место под среду. `.venv` не переносится между компьютерами: после копирования исходников среда создаётся заново. Все пути разрешаются относительно файла запуска, поддерживаются пробелы и кириллица. Диагностика сохраняется в `.runtime/setup.log`, ошибки окна — в `.runtime/app-error.log`. Кэш Matplotlib также находится внутри `.runtime`.

После подготовки запускается `gui.py`. Окно содержит работающие кнопки проверки GRU, объяснения модели, схемы и состояния проекта. Обучение на полном наборе и прогноз пока отключены с пояснениями. Небольшая техническая проверка модели выполняется в фоне и не блокирует окно.

## Целевая среда полной программы

| Компонент | Решение |
|---|---|
| Основная ОС по ТЗ | Ubuntu 24.04 |
| Разработка на имеющемся ПК | Windows, Python 3.12; отдельная проверка Ubuntu перед приёмкой |
| Вычисления | CPU; 16 ГБ памяти и Ryzen 5 4600H или аналог по ТЗ |
| Обучение и прогноз | PyTorch |
| Работа с таблицами и массивами | NumPy 2.3.5, pandas 2.3.3 |
| Графики журнала обучения | Matplotlib 3.10.7 |
| Модель | PyTorch 2.9.1+cpu |
| Окно программы | tkinter, входящий в Python |
| Установка | `.venv`, requirements.txt, requirements-torch.txt и requirements-windows.lock.txt |
| Хранение | Данные в ../data-project; модели и результаты в models, results |

CPU-установка этой версии приведена в [официальной инструкции PyTorch](https://pytorch.org/get-started/previous-versions/#v291). Установленный набор проверен на этом Windows ПК; проверка Ubuntu остаётся отдельным этапом. Для технических проверок используются `python run.py verify-model` и `python -m unittest discover -s tests -v` из подготовленной среды.

После установки программа и проверка GRU работают автономно. Дорожные данные не скачиваются: единый датасет находится в ../data-project. Docker, облако, API-сервис, база данных и видеокарта не нужны. По запросу пользователя от 26 ноября добавлена локальная оболочка с кнопками; консольные команды для приёмки по ТЗ сохраняются.

## Поведение единого меню после интеграции

1. **Прогноз:** выбрать CSV и время t; проверить историю и наличие модели; выдать результат в консоль и JSON.
2. **Обучение:** явный выбор пользователя; проверить данные; обучить и сохранить лучшие веса с журналом.
3. **Оценка:** отдельный запуск на test с сохранением метрик и решений обоих алгоритмов.
4. **Проверка готовности:** показать наличие среды, входа, весов и совместимость настроек.
5. **Архитектура:** открыть объяснение устройства проекта.

При отсутствии модели меню объясняет, что обучение ещё не выполнено или веса не получены. При отсутствии CSV показывает требуемый формат. Параметры запуска выбираются внутри меню, чтобы обычному пользователю не приходилось запоминать команды.

## Отдельные команды после интеграции

Доступны команды `validate` и `prepare`, использующие единый датасет задержек. Они не требуют сторонних библиотек и не создают дубли CSV. Команды `train`, `evaluate`, `predict` пока зарезервированы.

Веса и журнал обучения, метрики теста и результат отдельного прогноза хранятся раздельно. Повторный прогноз не меняет лучшую модель. Запуск оценки не запускает обучение автоматически.
