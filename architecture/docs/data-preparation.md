# Подготовка данных проекта СМ7 по ТЗ версия 2

Этот модуль реализует только часть ответственного за данные. Он совместим с `docs/interfaces.md` и `config.json` из обновления архитектуры от 25 ноября 2026 г. Старые задержки из `data-project/traffic_delays.csv` не используются: новая постановка задачи опирается на плотность потока, а не время ожидания.

## Установка и запуск

Из каталога `architecture` (Python 3.12):

```bash
python -m pip install -r requirements-data.txt
python run.py generate
python run.py validate
python run.py prepare
python -m unittest discover -s tests -v
```

Генератор, проверка и подготовка доступны независимо от нейросети и не требуют PyTorch, GPU или подключения к интернету после установки NumPy. `generate` создаёт файл `data/traffic_density.csv` по `data/generator_config.json`. `validate` проверяет исходный CSV; `prepare` дополнительно создаёт `results/data_report.json`, `data/control/history.csv` и `data/control/actual.json`. Повторная генерация даёт одинаковые байты. Ошибка данных сопровождается ненулевым кодом и сообщением в stderr. Входные файлы при чтении и проверке не изменяются. CLI принимает абсолютные пути и пути относительно каталога `architecture`, даже при запуске из другой папки.

## Синтетический источник

Каждая строка соответствует завершившемуся пятиминутному интервалу. Период с 1 января 2024 г. до 1 января 2026 г. включает 731 сутки и 210 528 наблюдений. Метка времени — конец интервала. Час и день недели определяются по середине интервала.

Для трёх участков одной полосы по 100 м используется формула из ТЗ:

`n_i = clip(2 + c * (a_i * f(h, 8) + b_i * f(h, 18)) + noise_i, 0, 20)`

`f(h, p) = max(1 - abs(h - p) / 3, 0)`

Коэффициент `c` равен 1 в будни и 0,7 в выходные. Пары коэффициентов `(a, b)` — `(10, 4)`, `(4, 10)`, `(7, 7)`. Шум выбирается независимо из `uniform(-2, 2)` с тремя отдельными `random.Random(43)`, `random.Random(44)`, `random.Random(45)`. Плотность в автомобилях/км одной полосы равна `10 * n_i` и округляется до одного знака после запятой. Итоговый набор искусственный; наблюдений с дорожных датчиков в нём нет.

## Формат и разбиение

CSV в UTF-8: `timestamp,density_1,density_2,density_3`. Проверяется точный период, количество строк, поля, возрастающее время и шаг 5 минут, отсутствие пропусков и повторов, конечность, диапазон и точность плотностей.

| Часть | Строки | Окна |
|---|---:|---:|
| train | 147 369 | 147 357 |
| validation | 31 579 | 31 567 |
| test | 31 580 | 31 568 |

Сначала строки делятся хронологически, затем независимо в каждой части формируются окна. История включает 12 строк, от `t-55 минут` до `t`; правильный ответ — номер минимальной плотности строки `t+5 минут`, минус единица. При равенстве выбирается первый минимум. Поэтому 12 последних строк каждой части нельзя использовать как начало полноценного входного окна с целевой строкой, и число примеров равно числу строк минус 12. Вход содержит только прошлые плотности. Перемешивание оставлено модулю обучения (только train).

## Подключение к модулю обучения

```python
from src.sm7.data_adapter import load_training_splits, load_test_split, load_history

train, validation = load_training_splits('data/traffic_density.csv', 'config.json')
# train.X: np.ndarray float32 [147357, 12, 3], исходные единицы 0..200
# train.y: np.ndarray int64 [147357], классы 0, 1, 2
# train.forecast_origin: np.ndarray Unicode ISO-меток [147357]

# Только отдельный этап итоговой оценки:
test = load_test_split('data/traffic_density.csv', 'config.json')
# test.target_density: np.ndarray float32 [31568, 3], только для метрик

# Прогноз без будущих данных:
X, t = load_history('data/control/history.csv', '<t из actual.json>', 'config.json')
# X.shape == (12, 3); t — строка ISO
```

Модель получает `X / 200` только непосредственно в общем слое подготовки входа. Адаптер ничего не нормализует, не включает временные метки и правильный ответ в `X`, не обучает модель. При предоставлении `config.json` проверяется совместимость входных параметров с ТЗ. Для контроля история содержит именно первые 12 строк тестовой части; фактический ответ по тринадцатой хранится отдельно. `actual.json` — фактическая метка и не является эталоном результата GRU; эталонный прогноз с вероятностями создаётся после обучения.

## Интеграция с запуском

Файлы добавляются в одноимённые каталоги актуальной ветки проекта. В `run.py` подключены режимы `generate`, `validate` и `prepare` с переменными аргументами, также пункты добавлены в меню `START.cmd`. Остальные режимы сохранены: `train`, `evaluate` и `predict` остаются зарезервированными для их ответственных. Установка NumPy не требуется для просмотра архитектуры и статуса. Непосредственный запуск `python -m src.sm7.data_adapter ...` также поддерживается. В обучении и оценке используются соответствующие загрузчики из этого модуля. Для выдачи прогноза по сохранённым весам достаточно истории из 12 строк и времени окончания последней строки.

## Контроль качества

Тесты проверяют повторяемость, точное число строк, формы и типы массивов, отсутствие пересечения окон между выборками, правильность целевых меток, выбор меньшего номера при равенстве, принятие правильного окна без будущей строки, игнорирование будущей строки при построении X и отклонение пропусков, дублей, переставленного времени, устаревших данных относительно запрошенного t, неверных колонок, нечисловых/бесконечных значений, плотности 201 и истории из 11 строк. В исследованиях и обучении test не используется для выбора модели; полный CSV проверяется в соответствии с требованиями ТЗ, но тестовые окна не выдаются загрузчиком обучения.

Для короткой демонстрации правильной истории и обоснованного отказа:

```bash
python run.py validate --csv data/control/history.csv --time 2025-09-13T09:20:00
python run.py validate --csv data/control/invalid_gap.csv --time 2025-09-13T09:20:00
```

Во втором файле специально удалено наблюдение 08:50, поэтому он должен отклоняться. Фактическая плотность в следующем интервале после контрольного t составляет `[62.5, 28.9, 48.9]`; правильный номер — 2. Эти значения не передаются во вход модели.
