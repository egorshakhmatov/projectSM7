# Календарные признаки датасета задержек

Основной датасет — `data-project/traffic_delays.csv`, 70 176 последовательных наблюдений в UTC с 2024-01-01 00:00 до 2025-12-31 23:45, шаг 15 минут. Задержки A/B/C, исходные скорости, происхождение, контрольные окна и хронологическое разбиение сохранены без изменения. Дополнительный CSV не требуется.

| Столбец | Значение |
|---|---|
| `timestamp_utc` | Уникальная временная отметка UTC |
| `date`, `day`, `month`, `year` | Местная дата Чикаго, число, месяц, год |
| `day_of_week` | 1 = понедельник, 7 = воскресенье |
| `time` | Местное время Чикаго, HH:MM |
| `is_weekend` | 1 для субботы/воскресенья, иначе 0 |
| `is_holiday` | 1 для регулярно отмечаемого федерального праздника США по календарю OPM, иначе 0 |
| `is_nonworking_day` | 1, если праздник или выходной, иначе 0. Это календарный индикатор, а не доказательство отсутствия работы всех организаций. |
| `utc_offset_minutes` | Смещение −360 (CST) или −300 (CDT); различает повторяющийся местный час осенью |
| `delay_A`, `delay_B`, `delay_C` | Задержки по направлениям, минуты |
| `source`, `window_ok`, `speed_*`, `source_time_*` | Исходные поля происхождения и проверок; пустые скорости синтетических строк сохранены |
| `split` | Последний столбец: train, validation или test |

Календарь соответствует месту происхождения городских данных — Чикаго, США. Сезонное время рассчитывается по правилам [NIST](https://www.nist.gov/pml/time-and-frequency-division/popular-links/daylight-saving-time-dst). Праздники — ежегодные общенациональные даты по [OPM](https://www.opm.gov/policy-data-oversight/pay-leave/federal-holidays/), с обычным переносом на пятницу или понедельник; региональные праздники и разовые закрытия государственных учреждений не включены. UTC используется для хронологии и проверки шагов. Первые шесть часов UTC 2024 года относятся к 31 декабря 2023 года по местному времени.

| Выборка | Строк |
|---|---:|
| train | 49 123 |
| validation | 10 526 |
| test | 10 527 |
| Всего | 70 176 |

Воспроизведение календарных полей (Python 3.12, только стандартная библиотека):

```bash
python data-project/prepare_calendar.py data-project/traffic_delays.csv data-project/traffic_delays.csv
```

Уточнение для разработчика модели: календарные признаки теперь доступны в таблице, но включение их в тензор GRU зависит от согласованной архитектуры. `split`, `source` и `window_ok` не должны использоваться в качестве входных признаков модели. Исходные задержки не пересчитываются, временная сетка не интерполируется. Формат данных для регрессии задержек через 60 минут соответствует описанию `readmeabtraffic.md`.
