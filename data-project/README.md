# Данные для прогноза задержек у трёх светофоров

Единственный актуальный датасет направления — `traffic_delays.csv`: 70 176 последовательных наблюдений за 2024–2025 годы в UTC с шагом 15 минут. В постановке задачи по восьми последним наблюдениям прогнозируются три задержки через 60 минут; рекомендуется направление с минимальным прогнозом. Задержки выражены в минутах.

## Формат CSV — семь столбцов

| Поле | Значение |
|---|---|
| `timestamp` | Дата и время Чикаго в ISO 8601 с UTC-смещением (−06:00 зимой, −05:00 летом) |
| `is_holiday` | 1 — регулярно отмечаемый федеральный праздник США по календарю OPM, иначе 0 |
| `is_weekend` | 1 — суббота или воскресенье по местному времени, иначе 0 |
| `delay_A`, `delay_B`, `delay_C` | Оценки дополнительных времён проезда в минутах |
| `split` | `train`, `validation` или `test` (последняя графа) |

Первое наблюдение: `2023-12-31T18:00:00-06:00,0,1,0.015,0.2685,0.1145,train`. Оно соответствует 1 января 2024 года, 00:00 UTC. Временная сетка равномерна в UTC, а местное время отражает календарь Чикаго и смену летнего времени. Дата, месяц, день недели и часы при необходимости извлекаются из `timestamp`. Праздники отражают ежегодный общефедеральный календарь, а не разовые и региональные выходные. Источники: [OPM](https://www.opm.gov/policy-data-oversight/pay-leave/federal-holidays/), [правила перехода NIST](https://www.nist.gov/pml/time-and-frequency-division/popular-links/daylight-saving-time-dst).

## Происхождение и качество данных

30% строк (21 053) — расчётные задержки на основе опубликованных оценок скорости по участкам Чикаго; 70% (49 123) — статистически сгенерированные значения. Непосредственных замеров времени ожидания у стоп-линии в наборе нет. Это учебные направления на разных улицах, не три выезда с одного перекрёстка.

Источник скорости — [Chicago Traffic Tracker, исторические оценки по участкам](https://data.cityofchicago.org/d/4g9f-3jbs), основанные на GPS автобусного движения. За каждый интервал `(t−15 мин, t]` использована последняя пригодная оценка на каждом из трёх участков. Неоднозначные отметки времени, конфликтующие дубликаты и неположительные скорости исключены; при формировании квоты предпочтены непрерывные блоки.

| Направление | ID | Участок | Длина, мили | Опорная скорость, mph |
|---|---:|---|---:|---:|
| A | 419 | 79th, State → Vincennes, запад | 0,49 | 26 |
| B | 1270 | Madison, Wacker → Halsted, запад | 0,54 | 23 |
| C | 407 | Western, Bryn Mawr → Foster, юг | 0,50 | 29 |

Задержка рассчитана как `max(0, 60 × L/v − 60 × L/v_ref)` в минутах; `v_ref` — 90-й процентиль скорости по городским строкам train. Это дополнительное время проезда всего участка, на которое могут влиять заторы и светофоры.

Для синтетических строк использованы почасовые медианные профили задержек train, отдельно по направлениям, будням и выходным, с интерполяцией между часами и общими/индивидуальными колебаниями, сезонностью и затухающими заторами. Параметры не подбирались на validation/test. Начальные состояния генератора для трёх выборок — 42, 43 и 44. Отрицательные задержки исключены.

## Разбиение и формирование окон

| Выборка | Строк | Расчётные | Синтетика | Допустимые окна |
|---|---:|---:|---:|---:|
| train | 49 123 | 14 737 | 34 386 | 45 040 |
| validation | 10 526 | 3 158 | 7 368 | 9 746 |
| test | 10 527 | 3 158 | 7 369 | 9 852 |
| Всего | 70 176 | 21 053 | 49 123 | 64 638 |

Разбиение хронологическое, 70/15/15. Для момента `t` история — 8 строк от `t−105 мин` до `t` включительно, ответ — три задержки из строки `t+60 мин`. Вход и ответ не пересекают границу выборки или смены источника. Календарные признаки доступны для включения в модель; существующий адаптер `load_split` возвращает три задержки на каждом шаге, исходные метки происхождения отдельно. `split` не является признаком модели.

`provenance.json` — компактная карта диапазонов расчётных наблюдений; остальные строки синтетические. Она восстанавливает исключённые технические флаги и предотвращает изменение состава обучающих окон. Это не второй датасет; контрольная сумма привязывает карту к CSV. Полные исходные скорости и методика доступны в [предыдущей версии репозитория](https://github.com/egorshakhmatov/projectSM7/tree/aa4144b5c6389add293939e02d0e31b5d51d0c60/data-project).

## Проверка и загрузка

Из корня репозитория:

```bash
python data-project/prepare_data.py
```

Скрипт без сторонних библиотек проверяет формат, 15-минутный шаг, конечность и неотрицательность задержек, границы выборок и происхождения. Из папки `data-project` в Python:

```python
from prepare_data import load_split
X_train, y_train, source_train = load_split('train')
# X_train: 45040 × 8 × 3; y_train: 45040 × 3
```

## Защита от некорректных сторонних данных

Основной набор защищён проверками фиксированного периода, контракта семи полей и контрольной суммы карты происхождения. Сторонний CSV нельзя автоматически подставить в обучение. Сначала проведите отдельный аудит, не изменяющий ни проверяемый файл, ни основной датасет:

```bash
python data-project/prepare_data.py --audit "other_data.csv"
```

Для воспроизводимой проверки исторического эксперимента задайте дату отсечения, например:

```bash
python data-project/prepare_data.py --audit "other_data.csv" --as-of 2026-01-01T00:00:00+00:00
```

По умолчанию дата отсечения — текущее время UTC. Результат аудита — JSON с временем начала и конца, количеством строк и уникальных отметок, пропусками по полям, ошибками и предупреждениями (код, число срабатываний, примеры номеров строк). Код завершения 1 и статус `rejected` означают отклонение; код 0 и статус `manual_review_required` означают, что формат прошёл проверку, но происхождение и метод расчёта должны быть согласованы до подключения к обучению.

| Проверка | Реакция |
|---|---|
| Дубликаты, пропуски, неправильный шаг или нарушенный порядок времени | Ошибка |
| Фактическое наблюдение позже даты отсечения | Ошибка |
| Train появляется после validation/test; validation после test | Ошибка: нарушение хронологии |
| Лишний или отсутствующий столбец, пустое значение, NaN, бесконечность, отрицательная задержка | Ошибка |
| Неверный календарный флаг, недостаточно строк для формирования окна | Ошибка |
| Отклонение долей выборок более чем на 5 п. п. от 70/15/15 | Предупреждение |
| Постоянная задержка, максимум больше 60 минут, сильное смещение медианы | Предупреждение для ручной проверки, не автоматическое отбрасывание |
| Не подтверждён источник и календарь праздников | Предупреждение; до согласования файл не принимается в обучение |

### Как предотвращается утечка будущего

При прогнозе в 12:00 модель использует только восемь наблюдений по 12:00 включительно; фактические задержки в 13:00 — цель y, а не часть входа X. Все 12 строк (8 входных + 4 до цели) принадлежат одной выборке и одному источнику. Train, validation и test идут последовательно по времени. Любые параметры нормализации и преобразований при дальнейшем обучении оцениваются только по train. Test не используется для настройки модели.

Аудит обнаруживает временные нарушения и подозрительные дополнительные столбцы, но один CSV не доказывает, что исходные задержки не были рассчитаны с использованием будущих сведений: это проверяется по методике и происхождению данных. Для внешнего файла число возможных окон считается только по границам выборок, до подтверждения источников; это не число принятых обучающих примеров.

### Дополнительная диагностика

Для каждого направления и каждой выборки выводятся число наблюдений, минимум, среднее, медиана, 95-й процентиль (nearest rank), максимум и доля нулей. Сильное изменение медианы между train и validation/test отмечается, если абсолютная разность превышает максимум из 0,1 минуты и p95 train. Эти пороги — диагностические эвристики, а не критерии физической невозможности. Статистика test используется для отчёта о качестве набора, не для настройки генератора, модели или преобразований.

Предыдущий режим миграции `--source` допускается только в отдельную пустую по отношению к датасету папку; существующий CSV и карта происхождения не перезаписываются.

Сравнивать GRU и базовый прогноз последнего значения нужно на одинаковых окнах с MAE, долей правильного выбора направления и средней дополнительной задержкой. При нескольких одинаковых фактических минимумах выбор любого минимального направления корректен.

Для дальнейшей проверки на реальной дороге можно собирать прямые измерения с камеры: измерять время проезда между двумя границами зоны и вычитать время свободного проезда; время неподвижности — отдельный показатель.
