# Данные для прогноза задержек через час

version 1.0

`traffic_delays.csv` содержит 70 176 наблюдений с 1 января 2024 года по 31 декабря 2025 года. Шаг — 15 минут, время — UTC, задержки выражены в минутах. По восьми последним наблюдениям модель прогнозирует три задержки на момент `t + 60 минут`. Затем программа выбирает направление с меньшей прогнозируемой задержкой. При точном равенстве порядок выбора — A, B, C.

В этой версии **30% строк содержат расчётную задержку по реальным оценкам дорожной скорости**, а **70% строк сгенерированы**. Прямых измерений задержки у стоп-линии в наборе 0%. A, B и C — три учебных направления, представленные тремя участками улиц Чикаго. Их нельзя выдавать за три альтернативных выезда с одной площадки. Для такой проверки нужны измерения на трёх реальных выездах с сопоставимым временем подъезда.

## Что в файле

| Выборка (`split`) | Строк | По измеренным скоростям | Синтетика | Допустимых окон по скоростям | Допустимых синтетических окон |
|---|---:|---:|---:|---:|---:|
| `train` — обучение | 49 123 | 14 737 | 34 386 | 12 680 | 32 360 |
| `validation` — подбор настроек | 10 526 | 3 158 | 7 368 | 2 751 | 6 995 |
| `test` — итоговая оценка | 10 527 | 3 158 | 7 369 | 2 784 | 7 068 |
| Всего | 70 176 | 21 053 | 49 123 | 18 215 | 46 423 |

Пропорция **70/15/15** относится к делению по времени на обучение, валидацию и тест. Пропорция **30/70** относится к происхождению исходных строк внутри каждой части. Число строк округлено до целого. Доли готовых окон немного отличаются, потому что часть из них пересекает границы выборок или источников.

| Поле | Значение |
|---|---|
| `timestamp_utc` | Момент `t`, к которому привязаны три значения. Формат ISO 8601, суффикс `Z` означает UTC. |
| `split` | Часть набора: `train`, `validation` или `test`. |
| `delay_A`, `delay_B`, `delay_C` | Оценка дополнительного времени проезда соответствующего участка в минутах. |
| `source` | `observed_proxy` — вычислено по опубликованным дорожным скоростям. `synthetic` — сгенерировано. |
| `window_ok` | `1` — для момента `t` есть допустимые вход и ответ. `0` — этот момент пропускаем при построении обучающих примеров. |
| `speed_A_mph` … `speed_C_mph` | Исходные оценки скорости в милях в час. У синтетических строк значения пустые. |
| `source_time_A_utc` … `source_time_C_utc` | Время исходного наблюдения для каждого участка. У синтетических строк значения пустые. |

## Как получена задержка по данным Чикаго

Источник — [Chicago Traffic Tracker, исторические оценки по участкам за 2024–2026 годы](https://data.cityofchicago.org/d/4g9f-3jbs). Город рассчитывает оценки скорости по GPS-наблюдениям автобусов CTA. Выбраны три направленных участка близкой длины с хорошей полнотой данных. [Описание архива и полей](https://data.cityofchicago.org/api/views/4g9f-3jbs).

| Ряд | ID | Участок | Длина, мили | Опорная скорость, mph |
|---|---:|---|---:|---:|
| A | 419 | 79th, на запад, от State до Vincennes | 0,49 | 26 |
| B | 1270 | Madison, на запад, от Wacker до Halsted | 0,54 | 23 |
| C | 407 | Western, на юг, от Bryn Mawr до Foster | 0,50 | 29 |

1. Местное время Чикаго переведено в UTC. Неоднозначные отметки при переводе часов и конфликтующие дубликаты исключены. Записи без положительной скорости не использованы.
2. Для каждого участка в интервале `(t − 15 минут, t]` взята последняя доступная оценка скорости. Строка считается пригодной, когда есть скорости для всех трёх участков. Для квоты 30% преимущество отдано длинным непрерывным блокам. Из-за такого отбора хорошо наблюдаемые периоды представлены сильнее.
3. Для каждого участка опорная скорость `v_ref` — 90-й процентиль скорости только по отобранным городским строкам `train`. Для всех выборок используется одна и та же опора.
4. Задержка вычислена как `max(0, 60 × L / v − 60 × L / v_ref)`, где `L` — длина в милях, `v` — опубликованная скорость в милях в час. Например, для участка в полмили при 15 mph и опоре 30 mph оценка составит `2 − 1 = 1` минуту.

Расчёт охватывает весь участок дороги. На него могут влиять светофоры, заторы и особенности наблюдений по автобусам. Он годится для учебной отработки подготовки данных и сравнения алгоритмов. Чтобы подтвердить качество прогноза времени ожидания у конкретного светофора, потребуется отдельный тест с прямыми измерениями там.

## Как сформирована синтетика

Для каждого направления построен отдельный суточный профиль. Профиль — почасовые медианы расчётной задержки по `train`, отдельно для будней и выходных. Между часами значения плавно меняются. Для редких сочетаний с недостатком данных используется медиана направления. Городская часть `validation` и `test` при настройке генератора не использовалась.

К профилю добавлены общие и отдельные для каждого участка колебания, различия между днями, слабая сезонность и редкие заторы, которые затухают за несколько шагов. Связь соседних случайных отклонений оценена по подряд идущим строкам `train`. Генератор стартует независимо для каждой части с начальными значениями случайного генератора `42`, `43` и `44`. Физический минимум задержки — ноль.

На обучающей части виден суточный рисунок. Например, медианная задержка для B по городским скоростям выросла с 0,06 мин ночью до 0,50 мин вечером. В синтетике для B — с 0,10 до 0,46 мин соответственно. Ночь здесь — с 01:00 до 05:00, вечер — с 17:00 до 19:00 по времени Чикаго. Различия между источниками учитывайте при сравнении прогнозов.

## Как получить X и y для модели

Строки упорядочены по времени. Сначала выделяем выборку по столбцу `split`. Для строки `k` с `window_ok = 1` вход `X` — задержки из строк `k−7 … k`, ответ `y` — задержки из строки `k+4`. Восемь входных отметок с шагом 15 минут занимают 105 минут между первой и последней. В обучение идут только три поля `delay_*`. Остальные столбцы служат для подготовки и контроля.

Например, для решения в 12:00 вход заканчивается строкой 12:00. Ответ берётся из 13:00, через четыре строки. Восемь входных строк и четыре последующие строки целиком принадлежат одной выборке и одному источнику. Если источник меняется между 12:00 и 13:00, такой пример пропускается, даже когда источник на концах совпадает.

Пример загрузки из папки с таблицей. CSV сохранён в UTF-8, разделитель — запятая. Для примера нужны `pandas` и `numpy`.

```python
import numpy as np
import pandas as pd

data = pd.read_csv("traffic_delays.csv", parse_dates=["timestamp_utc"])

def load_split(split):
    rows = data.loc[data["split"] == split]
    delay = rows[["delay_A", "delay_B", "delay_C"]].to_numpy(dtype=np.float32)
    t = np.flatnonzero(rows["window_ok"].to_numpy() == 1)
    x = delay[t[:, None] + np.arange(-7, 1)]
    y = delay[t + 4]
    origin = rows["source"].to_numpy()[t]
    return x, y, origin

x_train, y_train, _ = load_split("train")
print(x_train.shape, y_train.shape)  # (45040, 8, 3) (45040, 3)
```

Базовый прогноз для оценки — оставить три последние известные задержки без изменения (`X[:, -1, :]`). Сравнивайте его и обученную модель на одинаковых окнах. Считайте MAE в минутах для каждого направления, долю верных выборов и среднее дополнительное ожидание `фактическая задержка выбранного направления − минимальная фактическая задержка`. Если у нескольких вариантов одинаковая минимальная фактическая задержка, выбор любого из них считается верным. Результаты итогового теста полезно показать отдельно по источникам.

## Как в будущем измерять задержку камерой

Схема с техническим зрением подходит для прямого измерения **времени остановки**. Для каждого направления заранее задаётся зона контроля до стоп-линии. Камера ведёт один и тот же автомобиль по его временному идентификатору, а система оценивает движение по откалиброванному изображению. Порог скорости и минимальное время подтверждения остановки подбираются по размеченному видео.

При подтверждённой остановке таймер начинается с момента, когда машина перестала двигаться. При подтверждённом возобновлении движения текущий отрезок останавливается и записывается. Если машина остановилась снова до выезда из зоны, время новой остановки прибавляется к прежнему. Временную потерю трека лучше помечать как неполное наблюдение. Для обработки достаточно обезличенного идентификатора, направления, отметок времени и длительности.

Этот таймер измеряет только неподвижность. Чтобы измерять **задержку проезда участка**, как в текущей таблице, добавьте вторую границу зоны, фиксируйте вход и выход и вычитайте опорное время свободного проезда. Результаты можно усреднять по машинам, завершившим проезд к концу каждого 15-минутного интервала. Интервал без наблюдений помечается как пропуск, а машина без остановки имеет нулевое время остановки. Опорное время и правило агрегации фиксируются до обучения.

На защите эту схему можно представить так: «Для обучения и проверки прогноза мы подготовили набор из открытых дорожных наблюдений и синтетики. Для сбора прямых замеров предложена камера, которая отслеживает автомобиль в зоне перед стоп-линией и формирует запись о задержке».
